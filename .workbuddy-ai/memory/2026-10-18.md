## Mini App "No Telegram init data available" fix (13:20-13:30)

Root cause: `frontend/src/services/telegram.ts` captured initData ONLY via the SDK's
`retrieveRawInitData()` (@telegram-apps/bridge) = `tgWebAppData` parsed from the URL HASH
(sessionStorage fallback). The SDK's LaunchParamsSchema treats `tgWebAppData` as OPTIONAL —
validity needs only tgWebAppVersion/Platform/ThemeParams — so when the hash is absent/stripped
(the app itself does `history.replaceState({}, title, '/rooms')` in App.tsx; reloads/re-opens lose
it), retrieval SUCCEEDS but initData is undefined → "No Telegram init data available". The live
`window.Telegram.WebApp.initData` (valid for the whole WebView lifetime) was never read.
Also `retrieveRawInitData()` can THROW when no launch params exist at all (plain browser) —
unguarded at module scope (class field initializer).

Fix (frontend only, 2 files):
- `services/telegram.ts`: `safeRetrieveRawInitData()` try/catch wrapper; `getInitData()` now
  returns live `window.Telegram?.WebApp?.initData` first, SDK hash value as fallback.
- `contexts/UserContext.tsx`: clearer error text distinguishing "reopen from bot" vs
  "must be opened from the bot (not a plain link)".
Backend untouched (signature validation intact — /auth/telegram still 401s fake initData).
Frontend tsc exit 0; logic tests for 3 launch cases pass; served module verified via tunnel;
public chain: frontend /rooms 200, backend auth 401. NOT verified inside Telegram (no client
access) — user must close+reopen the Mini App from Play Bingo.
